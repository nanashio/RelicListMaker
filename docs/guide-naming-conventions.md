# 命名規約ガイド

このドキュメントは、RelicListMaker プロジェクト内でのファイル・フォルダ・関数名の命名規則をまとめたものです。既存コードや新規開発の際は本ガイドに従い、チーム内で一貫した命名を保ってください。

## 全般方針
- 原則として **英小文字** を用い、単語区切りにはアンダースコア（`_`）を使用します。
- 日本語名や CamelCase を避け、読みやすい英単語を組み合わせます。
- 略語は一般的なもの（`ocr`, `gui` など）に限定し、独自の略語を導入する場合はドキュメント化してください。

## フォルダ（ディレクトリ）命名
- プロジェクト直下のディレクトリは、役割を明確に表す名詞を使用します。
  - 例: `datasets`, `pipeline`, `templates`
- 複数単語を組み合わせる場合は `results_archive` のように snake_case とします。
- テスト用のフォルダは `tests` のように複数形を基本とします。
- 一時ファイルを扱うフォルダを作成する場合は `tmp`, `cache` などの汎用的な語を用い、不要になったら削除できる旨を README などに追記します。

## ファイル命名
- Python スクリプトは `snake_case.py` を用い、主な責務を表す動詞＋名詞、あるいは名詞のみで表現します。
  - 例: `relic_cli/commands/extract_frames.py`, `relic_pipeline/processing.py`
- 設定や定数をまとめたモジュールは `*_config.py`, `*_settings.py`, `*_constants.py` などとします。
- CLI エントリーポイントやアプリケーション本体は `__main__.py` のようにシンプルな名前を使用します（例: `relic_cli/__main__.py`, `gui/__main__.py`）。
- ドキュメント（Markdown）については「[ドキュメント命名](#ドキュメント命名)」を参照し、用途ごとのプレフィックスを必ず付与します。
- 静的アセット（HTML, CSS, JS, 画像等）は、用途を示すプレフィックスとファイル種別を併記します。
  - 例: `viewer_styles.css`, `gallery_thumbnail.png`

## ドキュメント命名
- Markdown ドキュメントは `guide-`, `plan-`, `reference-` など用途を示すプレフィックスから開始し、続く語句は snake_case を用います。
  - 例: `guide-naming-conventions.md`, `plan-ocr-pipeline-refactor.md`, `reference-master-relics.md`
- プレフィックスは以下を目安に選定します。
  - `guide-`: 手順や運用ルールなど繰り返し参照するドキュメント。
  - `plan-`: 計画書、リファクタリング方針、ロードマップなどの一時的/将来検討資料。
  - `reference-`: 定義集やパラメータ一覧など参照用データ。
- Markdown 内の見出しはタイトルに合わせて `# ガイド名` のようにシンプルに表記し、ファイル名と過度に乖離させないようにします。
- ドキュメントを新規追加する際は、同カテゴリの既存ドキュメントと命名が揃っているか確認し、必要に応じて本ガイドを更新してください。

## Python 関数・メソッド命名
- PEP 8 に従い `snake_case` を使用します。
- 先頭には動詞を配置し、処理の意図が一目で分かるようにします。
  - 例: `load_master_relics`, `filter_recognized_items`
- ブール値を返す関数には `is_`, `has_`, `should_` などの接頭辞を付与します。
- プライベート関数や内部専用のヘルパーは `_normalize_text` のように先頭にアンダースコアを付けます。
- コールバックやイベントハンドラは `on_` で始め、接尾辞に対象を記述します（例: `on_submit_clicked`).

## クラス命名（参考）
- クラス名は PEP 8 に従い `CamelCase` を用います。
- GUI やサービス層のクラスは、末尾に `View`, `Controller`, `Service` など役割を示す語を付けます。
  - 例: `RelicGalleryView`, `OcrPipelineService`

## 例外的なケース
- サードパーティの仕様に従う必要があるファイル名（例: `package.json`, `README.md`）は、そのまま使用します。
- 実行スクリプトやシェルスクリプトで OS 慣習に合わせる必要がある場合は、該当慣習を優先します。

## レビューと更新
- 命名規則を外れる新規ファイル・フォルダ・関数を追加する際は、レビュワーに説明した上で本ドキュメントを更新してください。
- 命名に関する議論が発生した場合は Issue を立て、合意事項をここに反映します。
