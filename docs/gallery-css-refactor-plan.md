# gallery.css リファクタリング計画

## 1. コード分析
- ルートレベルで `body`、`h1` などページ全体のスタイルを定義。
- `.toolbar`、`.storage-controls` などツールバー周辺の UI 要素に対するスタイルが連続して記述。
- `.item` を中心としたカードレイアウトに関するスタイルがまとまっているが、状態別クラス（`.is-duplicate`、`.is-favorite` など）が散在。
- `.effect` ブロック内で状態（`.pending`、`.low-confidence`、`[data-status]`）に応じたバリエーションが多数定義されている。
- 共通するボタンスタイルや配色が複数箇所で繰り返されているが共通クラス化されていない。

## 2. 問題点の指摘
1. **デザイントークンの重複**: 色・余白・角丸などがハードコードされており再利用性が低い。
2. **ボタン系スタイルの重複**: `.toggle-duplicates`、`.favorite-toggle`、`.storage-controls button` などの構造が類似している。
3. **状態クラスのまとまり不足**: `.item-color-*` や `.effect.*` の状態指定が散らばっており、可読性が低い。
4. **構造セクションの境界が曖昧**: レイアウト、コンポーネント、ユーティリティが混在し全体像が把握しづらい。

## 3. 優先度提案
1. デザイントークンの導入で基調色・余白をまとめ、今後の調整コストを下げる。
2. ボタン系スタイルを共通クラス化し、`.toggle-*` や `.review-button` へ適用する。
3. 状態クラスをまとまりよく整理し、関連セレクタを近接させる。
4. ファイル内をセクションコメントで区切り、構造を明確化する。

## 4. 小ステップ実行計画
- **Step A**: `:root` にカラーパレットと余白・角丸などのカスタムプロパティを定義し、主要な既存スタイルを置き換える。
- **Step B**: ボタン系スタイルの共通クラス `.button` を追加し、既存のボタン／トグルに適用。
- **Step C**: `.item` と `.effect` 関連の状態クラスをセクション化し、近似プロパティのまとめ・重複削減を行う。
- **Step D**: セクションコメントを追加し、レイアウト／コンポーネント／ユーティリティの順で並び替える。
