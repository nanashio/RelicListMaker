# Template Gallery CSS リファクタリング計画

## 0. コード分析
- `templates/gallery.css` は約200行規模で、ギャラリー画面全体のスタイルを単一ファイルで定義している。
- ボタンや入力などのコンポーネントがセクション毎に散在し、同一または類似のスタイルが繰り返し記述されている。
- 色やスペーシングはハードコードされており、テーマ変更や共通調整が困難になっている。

## 1. 問題点
1. **共通スタイルの重複**: `.storage-controls button`, `.viewbox-button`, `.review-button` などのボタン系スタイルが個別に設定され、保守性が低い。
2. **セクション構造の不明瞭さ**: ファイル全体が機能順に並ぶが、コメントや論理的なグループ化が無く可読性が低い。
3. **色・余白の定義が分散**: 各要素が直接色値を持つため、全体のトーン調整が難しい。

## 2. 優先度提案
- 最優先: 重複スタイルの集約と構造化（問題1,2）
- 次点: 色や余白のカスタムプロパティ化（問題3）

## 3. 実施ステップ
1. ルートにテーマ用カスタムプロパティを定義し、既存色を集約する。
2. ボタン・入力などの共通スタイルをグループ化したセクションを設け、重複を除去する。
3. 残りのコンポーネントスタイルを論理セクション毎に並べ替え、コメントで区切る。
4. メディアクエリや特殊状態を末尾に集約し、既存機能との互換性を確認する。

## 4. 影響確認
- リファクタリング後、主要な UI コンポーネント（ツールバー、ビュー調整、ギャラリー項目）の視覚が変化していないことをブラウザで確認する。
- 必要に応じて `python viewer_server.py` などでローカル表示を確認する。

## 5. 未着手の課題
- CSS Modules / PostCSS などの導入検討は今回のスコープ外。

## 6. 進捗状況
- [x] ステップ1: 既存の色・スペーシングをカスタムプロパティ化し、状態色も共通変数に集約。
- [x] ステップ2: ボタンや入力系の共通スタイルを統合し、ホバー/フォーカスの色替えもカスタムプロパティ経由で一元化。
- [x] ステップ3: 状態別スタイルを`:is()`でまとめ、コメントセクションも整理。アイテム色セレクタも変数ドリブンに調整済み。
- [x] ステップ4: ビューワーでの表示確認。`viewer_server.py` を用いた目視チェックでスタイル崩れが無いことを確認済み。
